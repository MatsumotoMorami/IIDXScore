# IIDXScore AC+Omni 只读试迁移

`IIDXScoreDryRun.exe` 只读取 IIDXScore 数据库及曲库索引。它没有正式迁移参数，不注入游戏，不执行 SQLite 的 `INSERT`、`UPDATE` 或 `DELETE`。双击自动试算会在游戏根目录新建一份 JSON 报告，不会修改成绩数据库。

建议先退出游戏，避免读到游玩中尚未完成的成绩。把 `IIDXScoreDryRun.exe` 放到 **IIDX 根目录**（与 `bm2dx.dll` 同一层），然后直接双击。程序自动读取 `IIDXScore.ini`、`scores/IIDXScore.sqlite3`、当前 IIDX34 AC 索引和 `data_mods` 下的 Omni 索引；`ServerKey` 从数据库已有作用域自动识别。测试电脑不需要安装 Python，也不用填写参数。完成后将同目录生成的 `IIDXScore-试迁移报告-日期时间.json` 发回来即可。

若旧分使用的曲库索引已经被新包覆盖，程序会提示有旧作用域缺少对应索引，预测不完整。把**旧** `music_omni.bin` 放入 IIDX 根目录下的 `IIDXScoreLegacy` 文件夹，再双击测试即可。程序通过数据库记录的 SHA256 自动配对，绝不会把新索引冒充旧索引。

也可以在 PowerShell 中手动指定路径（通常不需要）：

```powershell
.\IIDXScoreDryRun.exe `
  --db 'C:\IIDX\scores\IIDXScore.sqlite3' `
  --ac 'C:\IIDX\data\info\0\music_data.bin' `
  --omni 'C:\IIDX\data_mods\ominimix\info\1\music_omni.bin' `
  --legacy 'C:\旧曲包\info\1\music_omni.bin' `
  --server-key 'default' `
  --report '.\试迁移结果.json'
```

手动模式下 `--server-key` 必须与数据库旧成绩的服务器作用域完全一致。`--omni` 要填**现在准备加载的最新 Omni 索引**；`--legacy` 要填**旧分当时使用的确切索引**。若旧分和最新 Omni 都来自同一份文件，可以把两个参数填为同一路径。`--report` 可省略，此时仅在终端显示汇总，不产生文件。

输出中的 `AC` 指已存入当前 AC 作用域的成绩，`legacy` 指旧索引对应作用域的成绩。它们只在内存中合并为 AC+Omni 预计结果。跳过原因和具体歌曲记录可在 JSON 的 `skipped_rows` 中查看。若所有来源都显示 0 条，需检查数据库与旧索引是否匹配，不能据此推断没有旧成绩。

本脚本的匹配规则与 IIDXScore 0.5.3 相同：当前 AC 已有的歌曲和谱面优先，Omni 补充缺少的部分；歌曲 ID 相同须核对标题字节、谱面序号和等级。旧 ID 在新索引不存在时，标题须在新旧索引各自唯一，且谱面等级相同，才按新 ID 合并。`remapped_rows` 列出改号记录。它只预测数据库合并结果，不能证明 Omni 曲包已在游戏里实际加载。
